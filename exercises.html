ExercisesOne each week, due before the next

Every exercise is written against your own project's next feature, so the five project options do not change what is asked. Every exercise delivers an artifact and a short justification of the design. From week 10 on, it also delivers the evidence for it. Keep your transcripts.

1Toolchain and first user stories

Set up the group's repository, a CI pipeline, an AI-assisted IDE and a coding agent. Choose your project from the menu. Then write the project's first five user stories with acceptance criteria, by hand.

Submit repository link with CI running · five user stories with acceptance criteria. Feeds M0.

2One story, three models

Give the same user story to three different models. Compare the three implementations against your own acceptance criteria, not against each other.

Submit the three implementations · a comparison against the criteria. Feeds M0, stories reviewed.

3Your project's agent configuration

Write the agent configuration for your repository: conventions, how to build, how to test, and what the agent may not touch. Then measure the same task with the configuration and without it.

Submit the configuration file · the before and after measurement. Feeds M1.

4One feature with a coding agent

Implement one small feature with a coding agent. Keep the full transcript. Mark every point where the agent claimed to be finished, and say whether it was.

Submit the merged feature · the full transcript with the claims marked. Feeds M1.

5Choose and apply an agentic workflow pattern

Match five given tasks to patterns, design a workflow for one task from your own project, and build a small prototype of it. The full brief is on the week 5 page.

Submit workflow diagram · short implementation or execution trace · half-page justification. Feeds M2.

6Specialized agents and explicit coordination

Extend your week 5 workflow with specialized agents and explicit coordination. Make it clear who decides, who checks, and who stops the loop.

Submit the extended workflow · the review record. Feeds M2.

7A ten-case evaluation

Build a ten-case evaluation for your workflow. Run it three times. Report the pass rate and the variance across runs. Then name one failure the evaluation did not catch.

Submit the ten cases · three runs with pass rate and variance · the missed failure. Feeds M2.

8Elicitation, twice

Have an agent elicit the requirements for your next feature from a persona. Then interview a real classmate about the same feature. Diff the two results and account for the differences.

Submit both requirement sets · the diff, with your reading of it. Feeds M3.

9Two designs, one ADR

Have an agent propose two designs. Write the architecture decision record choosing one, giving the rationale the agent did not state. Then implement against the ADR.

Submit the two proposals · the ADR · the implementation. Feeds M3.

10Criteria, tests, and what is missing

For each acceptance criterion of one feature, name the test that covers it. Report the criteria with no test. Then generate a second test suite from the criteria rather than from the code, and compare its coverage and mutation score with the agent's code-derived suite.

Submit the criteria-to-test mapping · both suites · the comparison. Feeds M3, the test adequacy argument.

A worked example of the mapping, All tests pass, is handed out in the exercise session. It is the in-class activity from week 5, scaled up and applied to your own code.

11Verify someone else's patch

Take a bug report from another group's system. Let the agent propose a patch. Verify the patch against the acceptance criteria, not against the tests the patch brought with it.

Submit the patch · your verification against the criteria. Feeds the final submission.

12Security triage

Run static analysis and dependency checks on your repository. Triage what comes back. Find one fabricated or outdated dependency the agent introduced, if there is one, and say how it got in.

Submit the triaged findings · the dependency finding, or a statement that there was none. Feeds the final submission.

13The accountability statement

Write your project's accountability statement: who approves what, on what evidence. The reference point is clause 1.03 of the Software Engineering Code of Ethics, which makes approval conditional on a well-founded belief.

Submit the accountability statement, with the final submission. Feeds the final submission.

Week 14 has no exercise. Groups present their system and the evidence behind it, and each student writes an individual reflection.
