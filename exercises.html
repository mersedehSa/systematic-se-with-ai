Exercise 5: Choose and apply an agentic workflow pattern

In your project group. Due before week 6. About three hours; a starter script with one model call and one tool call is provided.

Part A: Recognise and compare patterns

For each scenario, choose a workflow pattern and justify it. Name one alternative and the trade-off. Say first whether a simpler, non-agentic solution would do; "no pattern needed" is a valid answer if you can argue it.

  1. About fifty bug reports arrive in a week, some about the user interface, some about the database, some about performance. The team wants one prioritised report.
  2. A feature needs a change to the data model, the API, and two screens, and the parts depend on each other.

Part B: Design a workflow for your project

Pick one task from your project and one of the five patterns. Explain why it fits, why you prefer it to one alternative, which components take part (LLM calls, agents, tools, deterministic checks, human decisions), and how you know the workflow is finished. Draw a simple diagram. Do not add agents the task does not need.

Part C: Prototype and reflect

Build a minimal demonstration with an AI tool, a short script, or a framework. Run it on one real example from your project and save the trace. Note what worked, what did not, and whether the pattern was the right choice.

Submit diagram, trace or screenshots, half-page justification.

Before next week: when is one agent enough, and when might several specialized agents help?

Reading: Anthropic, Building effective agents (2024). Optional: Shinn et al., Reflexion (NeurIPS 2023).
