Exercises

One each week, due before the next

Course›Exercises

Every exercise is written against your own project, so the five project options do not change what is asked. Each one delivers an artifact and a short justification of the design. In Block I you build that foundation by conventional means; from week 4 the same project is developed with agents, and from then on you keep the transcripts.

Block I · Software engineering fundamentals

1Toolchain, project choice, first user stories

Set up the group's repository and a CI pipeline. Choose your project from the menu. Then write the project's first user stories with acceptance criteria, by hand.

Submit repository link with CI running · user stories with acceptance criteria. Feeds M0.

2Specify one feature with acceptance criteria

Take one feature of your project and specify it properly: what it must do, and the criteria by which anyone could later decide whether it does.

Submit the specification with its acceptance criteria. Feeds M1.

3Test one feature, and review a peer's

Write tests for your feature from its acceptance criteria, not from the code. Then review another group's feature and say what their tests do not cover.

Submit the test suite with the criteria it maps to · your review of the peer feature. Feeds M1.

Block II · LLMs and agents

4One story, three models

Give the same user story to three different models. Compare the three implementations against your own acceptance criteria, not against each other.

Submit the three implementations · a comparison against the criteria. Feeds M1.

5Choose and apply an agentic workflow pattern

Three parts: recognise and compare patterns across five scenarios, design a workflow for one task from your own project, then build a minimal prototype of it and say whether the pattern was right. The full brief is on the week 5 page.

Submit workflow diagram · execution trace or screenshots · half-page design justification. Due before week 6.

6Build a feature with your pattern and specialized agents

Build one real feature of your project with the workflow pattern you chose in week 5, this time using specialized agents with explicit coordination: who decides, who checks, who stops. Keep the full transcript.

Submit the merged feature · the workflow as built · the full transcript · the review record. Feeds M2.

Block III · AI across the software engineering lifecycle

7Elicitation, twice, and one ADR

Have an agent elicit the requirements for your next feature from a persona. Then interview a real classmate about the same feature and diff the two. Write the architecture decision record for the design you pick, giving the rationale the agent did not state.

Submit both requirement sets with the diff · the ADR. Feeds M2.

8Port your workflow to a framework

Take the week 6 workflow and rebuild it on an orchestration framework or an agent SDK. Compare it with your hand-built version: what the framework gave you, what it cost, and whether a plain loop would have been enough.

Submit the ported workflow · the comparison, with a recommendation. Feeds M3.

9Security triage of your own code

Run static analysis and dependency checks on your repository. Triage what comes back. Find one fabricated or outdated dependency the agent introduced, if there is one, and say how it got in.

Submit the triaged findings · the dependency finding, or a statement that there was none. Feeds M3.

10Criteria, tests, and what is missing

For each acceptance criterion of one feature, name the test that covers it. Report the criteria with no test. Then generate a second suite from the criteria rather than from the code, and compare its coverage and mutation score with the agent's code-derived suite.

Submit the criteria-to-test mapping · both suites · the comparison. Feeds M3, the test adequacy argument.

11Verify someone else's patch

Take a bug report from another group's system. Let the agent propose a patch. Verify the patch against the acceptance criteria, not against the tests the patch brought with it.

Submit the patch · your verification against the criteria. Feeds the final submission.

12Threat model your agent setup

Treat your own agent configuration as an attack surface. Where could a prompt injection enter, which tools could be misused, and what does your supply chain assume? Say what you would change.

Submit the threat model · the mitigations you would apply. Feeds the final submission.

Block IV · Judgement and synthesis

13The accountability statement

Write your project's accountability statement: who approves what, on what evidence. The reference point is clause 1.03 of the Software Engineering Code of Ethics, which makes approval conditional on a well-founded belief.

Submit the accountability statement, with the final submission. Feeds the final submission.

14Presentation and reflection

Groups present the system and the engineering evidence behind it. Each student writes an individual reflection on what the semester changed about how they work.

Submit the group presentation · an individual reflection. Counts as the final 20 % of the portfolio.
