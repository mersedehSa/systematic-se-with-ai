Exercises

One each week, due before the next

Course›Exercises

One exercise a week, each applied to your own semester project, so the methods are practised on a system you are actually building. From week 9 the same project is approached again with AI support, which is what makes the comparison honest: there is something real to compare against.

The entries below are the planned exercise topics for each week. The detailed brief for an exercise, with its deliverables, is published in the week it is set. Week 11 is given in full because it accompanies the lecture shown in the teaching demonstration.

Block I · Software Engineering Foundations

1Software lifecycle and process selection

Work through a development scenario and choose a process model that fits its constraints: team size, requirement volatility, risk and release cadence. Set up the team repository and choose the project.

2Requirements elicitation, specification and quality

Elicit the requirements for your project and write them up, then assess them for quality: are they complete, unambiguous and testable?

3Architecture modelling and design decisions

Model the architecture of your system and record the decisions behind it, with the alternatives you rejected and why.

4Implementation, refactoring and code quality

Implement a feature against its acceptance criteria, refactor it, and review another team's code.

Block II · Software Quality and Evolution

5Test design

Design tests from the specification using equivalence partitioning and boundary value analysis, and write them as unit tests.

6Verification, validation, reviews and coverage

Review a peer artifact, measure coverage, and say what the coverage number does not tell you.

7Maintenance tasks, bug fixing and impact analysis

Take a change request against your system, analyse its impact, implement it, and show that nothing which previously worked has stopped working.

8Version control, CI/CD and automated quality checks

Put a pipeline on your repository that builds, tests and reports on every change, and make a failing check block it.

Block III · Systematically Developing Software with AI

9Identifying suitable ML and AI applications

Find the software engineering tasks in your own project where machine learning or AI would genuinely help, and the ones where it would not.

10Prompt engineering and evaluating LLM output

Produce software artefacts with an LLM and evaluate them: not whether they look right, but whether they meet the criteria you wrote earlier in the semester.

11Designing and applying an agentic workflow pattern

Select a workflow pattern for a software engineering task, explain the choice, apply the workflow, and critically evaluate the resulting artefacts. The full brief is on the week 11b page.

12Applying AI assistance across lifecycle activities

Take the AI-assisted artifacts you have produced across requirements, design, code and tests, and name the evidence that each is adequate, and the criteria with none.

Block IV · Professional Practice and Integration

13Professional, ethical and accountability issues

Evaluate the professional, ethical and accountability questions raised by AI-assisted development in your own project, and write the accountability statement. The reference point is clause 1.03 of the Software Engineering Code of Ethics.

14Final demonstrations, presentations and reflection

Teams demonstrate the system and the engineering evidence behind it. Each student writes an individual reflection.
