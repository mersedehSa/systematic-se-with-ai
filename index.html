Course overview

Software engineering across the lifecycle, with AI agents as participants

Course›Overview

The course treats AI agents as participants in software engineering activities rather than as a tool for isolated tasks. Each week takes a part of the lifecycle and asks two questions: what can an agent contribute here, and what evidence do we need before we accept what it produced. The goal is to systematically engineer software with AI.

Illustrative course concept, prepared for a university teaching demonstration, October 2026. This is a worked proposal for how such a module could be structured. It is not an offering, and no enrolment, submission or examination system stands behind it.

Format and assessment

Course frame. The credit and contact-hour figures are a proposed module allocation, chosen to be proportionate to comparable modules.

Level Bachelor Computer Science, 3rd semester
Credits and format 9 KP · lecture 4 SWS + exercise 2 SWS · 14 weeks, two lectures and one exercise each week
Prerequisites One programming language, and Git. The software engineering fundamentals are taught in Block I, so the course is self-contained.
Assessment Portfolio: semester group project 50 % · weekly exercises 30 % · final presentation and reflection 20 %

Each phase of the lifecycle is met twice: once as a fundamental in Block I, and once with agents in Block III. The second visit assumes the first, which is what lets the course ask where established practice runs out when an agent writes both the software and the tests for it.

What you look at over the semester

By the end of the course you can:

  • explain how AI agents participate in software engineering activities;
  • describe how agentic work can be organised as a process with explicit checks and termination;
  • assess whether an AI-produced artifact has been adequately verified, and name what is missing;
  • apply established software engineering practice to AI-produced output.

The third one is the spine of the course. Most weeks end by asking it about something an agent just produced.

How the semester is organised

Four blocks across 14 weeks: Software engineering fundamentals (weeks 1 to 3), LLMs and agents (weeks 4 to 6), AI across the software engineering lifecycle (weeks 7 to 12), and Judgement and synthesis (weeks 13 and 14).

Groups of three or four choose one of five systems in week 1. In Block I they specify, design and test it by conventional means, so that there is something to compare against. From week 4 the same project is developed with agents, feature by feature, and conventional engineering decisions can be set against AI-assisted alternatives. See the schedule, the weekly exercises and the semester project.

Using AI in this course

Use whatever tools you like. Document what you used. Never submit anything you cannot explain.

Transcripts are part of the deliverable, not an afterthought. The final submission includes an AI-use log with transcripts for every merged feature, and a statement of who approves what, on what evidence.

Before you start

The course teaches its own engineering fundamentals in Block I, so there is nothing you have to have read beforehand. What it does assume is that you can work in one language and use Git. All of the material below is open and free.

Git and continuous integration

Pro Git, Chacon and Straub, second edition, free to read in full online. Chapters 1 to 3 and 6 are enough. For continuous integration, the week 1 exercise walks you through setting up a pipeline on your own repository.

Python or Java basics

The Python Tutorial, Python Software Foundation, or Learn Java, the official Java tutorials. One language, well enough to read and review code you did not write.

If you want to read ahead

SWEBOK, Guide to the Software Engineering Body of Knowledge, IEEE Computer Society, free to download, for the process, requirements, design and testing chapters. For testing specifically, the ISTQB Certified Tester Foundation Level syllabus v4.0 is free and covers what Block I teaches. Neither is required.
