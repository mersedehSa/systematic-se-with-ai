Primary sources

Course›Resources

Papers, standards and codes the lectures draw on. Everything here is a primary source: the paper, the syllabus or the code itself, not a summary of it. Where a claim in the lecture comes with a number, it comes from one of these.

Agentic workflows and agents

Building effective agents

Anthropic, 19 December 2024. The patterns used in week 5, and the "when to use this workflow" notes behind the selection criteria.

LLM-Based Multi-Agent Systems for Software Engineering: Literature Review, Vision and the Road Ahead

He, Treude and Lo. ACM Transactions on Software Engineering and Methodology, 2025. arXiv:2404.04834. The source for the agent role names used across the lifecycle.

Reflexion: Language Agents with Verbal Reinforcement Learning

Shinn, Cassano, Berman, Gopinath, Narasimhan and Yao. NeurIPS 2023. arXiv:2303.11366. A published generate-check-revise loop, including the case where the loop underperforms its own baseline.

Evaluation and independence

LLM Evaluators Recognize and Favor Their Own Generations

Panickssery, Bowman and Feng. NeurIPS 2024. arXiv:2404.13076. Self-recognition correlates with the strength of self-preference.

Correlated Errors in Large Language Models

Kim, Garg, Peng and Garg. ICML 2025, PMLR 267. arXiv:2506.07962. Error correlation rises with shared developer, shared architecture, and with accuracy.

An Experimental Evaluation of the Assumption of Independence in Multiversion Programming

Knight and Leveson. IEEE Transactions on Software Engineering, SE-12(1), 1986, pages 96 to 109. The classical result: independence has to be engineered, not assumed. The earlier technical report version is open in the University of Virginia repository.

Testing

ISTQB Certified Tester Foundation Level, syllabus v4.0

International Software Testing Qualifications Board, 2023. Free download. Section 1.3 for the testing principles, 4.2 and 4.3 for black-box, white-box and defects of omission.

ISO/IEC/IEEE 29119-1:2022, Software and systems engineering. Software testing. Part 1: General concepts

ISO, IEC and IEEE, second edition, 2022. The standard vocabulary. The abstract and scope are readable without a licence.

Notes on Structured Programming (EWD249)

E. W. Dijkstra, 1969 and 1970, published in Dahl, Dijkstra and Hoare, Structured Programming, Academic Press 1972. The source of "program testing can be used to show the presence of bugs, but never to show their absence". It is not from "The Humble Programmer".

The Art of Software Testing, chapter 2

Myers, Sandler and Badgett, third edition, Wiley 2012. Why exhaustive testing is not a plan: roughly 100 trillion unique logic paths in a small program, and about a billion years to try them all.

AI-generated code

We Have a Package for You! A Comprehensive Analysis of Package Hallucinations by Code Generating LLMs

Spracklen and colleagues. USENIX Security 2025. arXiv:2406.10279. Note the spread between open-source and commercial models, and that hallucinated names recur.

Towards Mitigating API Hallucination in Code Generated by LLMs with Hierarchical Dependency Aware

Chen and colleagues. FSE 2025. arXiv:2505.05057. The asymmetry that matters for your project: public library APIs versus the project's own internal ones.

Are "Solved Issues" in SWE-bench Really Solved Correctly? An Empirical Study

Wang, Pradel and Liu. ICSE 2026. arXiv:2503.15223. Patches that pass the benchmark's tests and fail the project's own suite.

Professional practice

Software Engineering Code of Ethics and Professional Practice, version 5.2

ACM and IEEE Computer Society, 1999. Clause 1.03 is the one the course keeps returning to: approve software only on a well-founded belief that it is safe, meets specifications and passes appropriate tests.
